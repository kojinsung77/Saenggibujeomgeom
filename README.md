# 생활기록부 점검 웹서비스 v2.0

NEIS에서 내보낸 학생부 XLS 파일을 업로드하면 **Google Gemini AI** 또는 **완전 로컬 Ollama**로 기재요령 위반·중복 문장·띄어쓰기를 자동 점검하는 로컬 웹 도구입니다.

**제작**: JINSUNG

---

## 주요 특징

| 구분 | 내용 |
|------|------|
| **개인정보 보호** | 전 기능 `127.0.0.1` 로컬 실행, 외부 서버 전송 없음 |
| **AI 점검 (선택)** | Google Gemini API — 기재요령 위반·수정 제안 |
| **완전 로컬 검사** | Ollama 로컬 LLM — 개인정보 외부 전송 0, 무료 |
| **통합검사** | 글자수·규칙·중복 문장·띄어쓰기 4가지 한 번에 |
| **다크/라이트 + 팔레트** | 라이트·다크 + 파스텔 10색 테마 선택 |

---

## 전체 흐름

```
NEIS XLS 5종 다운로드
  → ① 업로드 탭: 파일 업로드 & DB 구축
  → ② 학생 조회 탭: 학년/반/이름/키워드 검색
  → ③ AI 점검 탭: Gemini로 일괄 점검 (실시간 진행률 + ETA)
  → ④ 통합검사 탭: 글자수·규칙·중복·띄어쓰기 로컬 검사
  → ⑤ 결과 확인 탭: 위반 내역 Excel 출력
```

## 설치 & 초기 설정 (최초 1회)

### 사전 준비

- **Python 3.11 이상** — `python --version`으로 확인. 없으면 [python.org](https://python.org)에서 설치 (설치 시 **"Add Python to PATH"** 체크 필수)
- **Git** — `git --version`으로 확인. 없으면 [git-scm.com](https://git-scm.com)에서 설치
- **Ollama** (선택, 로컬 띄어쓰기 검사용) — [ollama.com](https://ollama.com)에서 설치 후 모델 다운로드

### 1단계 — 저장소 클론

```bash
git clone https://github.com/tigerjk9/school-life-record.git
cd school-life-record
```

### 2단계 — 가상환경 생성

```bash
python -m venv .venv
```

### 3단계 — 패키지 설치

```bash
.venv\Scripts\activate
pip install -r requirements.txt
```

> FastAPI, Uvicorn, Pandas, google-generativeai 등 필요한 라이브러리가 모두 설치됩니다. 수 분 소요될 수 있습니다.

### 4단계 — (선택) Ollama 모델 설치

띄어쓰기 검사를 사용하려면 Ollama 서버와 모델이 필요합니다.

```bash
# Ollama 설치 후 서버 실행 (터미널 별도 창에서)
ollama serve

# 권장 모델 — 용량 순 (성능/속도 균형: gemma3:4b)
ollama pull gemma3:4b       # 2.5 GB, 권장
ollama pull llama3.2:3b     # 2.0 GB, 가벼움
ollama pull mistral:7b      # 4.1 GB, 고성능
```

### 5단계 — 완료 확인

설치가 끝나면 이후부터는 **bat 파일만 실행**하면 됩니다.

```
school-life-record/
├── .venv/               ← 가상환경 (git 제외됨)
├── backend/
├── frontend/
├── rules/               ← 연도별 기재요령 규칙 JSON
├── requirements.txt
└── 생기부점검_실행.bat  ← 이것만 더블클릭
```

## NEIS에서 파일 받기

NEIS 교육정보시스템에서 **학생부 항목별 조회(출력)** 메뉴를 이용합니다.

| 순서 | 항목명 | 비고 |
|------|--------|------|
| ① **필수** | 교과학습발달상황 | 학생 기준 정보 — 반드시 먼저 업로드 |
| ② | 세부능력및특기사항 | AI 점검 + 글자수·규칙·중복 검사 대상 |
| ③ | 창의적체험활동상황 | AI 점검 + 글자수·규칙·중복 검사 대상 |
| ④ | 봉사활동상황 | AI 점검 + 글자수·규칙 검사 대상 |
| ⑤ | 행동특성및종합의견 | AI 점검 + 글자수·규칙·중복 검사 대상 |
| ⑥ | 학년반이력 | 선택 — 학년별 반·번호 이력 보완 |

> 파일 형식은 **.xls 또는 .xlsx** 모두 지원합니다.

## 탭별 사용법

### ① 업로드 & DB 구축

1. 교과학습발달상황 파일을 드래그하거나 클릭하여 선택합니다. *(필수)*
2. 나머지 항목도 같은 방법으로 업로드합니다. *(점검할 항목만 올려도 됩니다)*
3. **DB 구축** 버튼을 클릭합니다.
4. 구축 완료 후 헤더의 **DB 상태** 뱃지가 초록으로 바뀌면 성공입니다.

> DB 구축 시 기존 데이터는 `data/record.db.bak.{timestamp}`로 자동 백업됩니다.

---

### ② 학생 조회

- **학년 / 반 / 이름** 필터로 특정 학생을 검색합니다.
- **내용 검색** 란에 키워드를 입력하면 세특·창체·봉사·행특 본문 전문 검색합니다.
- 학생 행을 클릭하면 항목별 기재 내용을 모달로 확인합니다.

---

### ③ AI 점검 (Gemini)

Google Gemini API를 사용하는 AI 기재요령 위반 점검입니다.

**API 키 발급**
1. [Google AI Studio](https://aistudio.google.com/) 접속 → 구글 계정 로그인
2. **Get API key** → **API 키 만들기** → `AIza...` 형태의 키 복사

> ⭐ 유료 티어(결제 계정 연결)가 성능·속도 면에서 훨씬 낫습니다. 무료는 분당 15회 요청 제한으로 오류가 잦습니다. 학급(30명) 점검 비용은 대개 수백 원 수준입니다.

**점검 순서**
1. API 키를 입력하고 **연결** 클릭 — 초록 뱃지로 바뀌면 성공
2. 사용할 **모델** 선택 (권장: `gemini-2.5-flash`)
3. **배치 크기** 설정 (기본 3 — API 오류가 잦으면 1로 낮추세요)
4. 점검 **영역**과 **학년/반** 선택 (비워두면 전체 점검)
5. **시스템 프롬프트** 안의 학교명을 **반드시 본교 이름으로 변경** 후 저장

   > ⚠️ 학교명을 변경하지 않으면 본교명이 위반으로 오탐됩니다.

6. **검사 시작** 클릭 — 실시간 진행률 + **남은 시간(ETA)** 표시

---

### ④ 통합검사 (로컬 — 개인정보 외부 전송 없음)

Gemini API 없이 로컬에서 실행하는 4가지 검사입니다.

#### 4-1. 글자수·바이트 검증

교육부 기재요령 기준 글자수 상한을 초과한 항목을 찾습니다.

1. **연도** 선택 (예: 2025)
2. 학년·반 필터 선택 (비워두면 전체)
3. **글자수 검사 시작** 클릭

결과 테이블에 각 항목의 글자수·상한·초과 여부가 표시됩니다.

#### 4-2. 기재요령 위반 패턴 검사

기업명·병원명·대학명·점수·성별·실명·수상명 등 규정 위반 패턴을 정규식으로 검사합니다.

1. **연도** 선택 (예: 2025)
2. **규칙 검사 시작** 클릭

심각도(high/medium/low)와 어떤 규칙에 걸렸는지, 근거 문자열이 함께 표시됩니다.

#### 4-3. 중복 문장 검출

학생 간·학생 내 동일·유사 문장을 찾습니다.

1. **유사도 임계값** 슬라이더로 기준 설정 (기본 70%)
2. 학생간 중복 / 학생내 중복 체크박스 선택
3. **중복 검사 시작** 클릭

유사도 비율과 공통 구절, 해당 학생·과목이 쌍으로 표시됩니다.

#### 4-4. 띄어쓰기 검사 (Ollama 필요)

Ollama 로컬 LLM으로 띄어쓰기 오류를 검사합니다. 개인정보가 외부로 전혀 나가지 않습니다.

**사전 준비**
```bash
# Ollama 서버 실행 (프로그램 실행 전, 별도 터미널)
ollama serve

# 모델 설치 (최초 1회)
ollama pull gemma3:4b
```

**검사 순서**
1. Ollama 상태가 **연결됨** + 모델 목록이 표시되면 준비 완료
2. **모델** 드롭다운에서 설치된 모델 선택
3. 학년·반 필터 선택 후 **띄어쓰기 검사 시작** 클릭

각 항목의 오류 수·오류 위치·교정 텍스트가 표시됩니다.

> ⚠️ 레코드 수가 많으면 시간이 오래 걸립니다. 처음에는 특정 반·영역만 선택해서 테스트하세요.

#### 4-5. 연도별 규칙 업데이트

GitHub에 공개된 최신 기재요령 규칙 파일을 자동으로 내려받습니다.

1. **GitHub Raw URL** 란에 규칙 파일 주소 입력
2. **규칙 종류** 선택 (기재요령 위반 / 글자수 상한)
3. **업데이트** 클릭 — `rules/` 폴더에 자동 저장

> 규칙 파일 형식: `violations_YYYY.json` / `limits_YYYY.json`

---

### ⑤ 결과 확인

1. **검사 이력** 드롭다운에서 확인할 회차를 선택합니다.
2. 상단 요약 배너에서 위반 건수·정상 건수를 확인합니다.
3. **필터**(전체/위반만/정상만)로 결과를 걸러봅니다.
4. 행 클릭 → 원문, 위반 근거, **수정 제안(After)** 모달 확인
5. **Excel 다운로드** → 요약·위반·정상·전체 4개 시트 xlsx 파일

## 주의사항 & FAQ

> **사용 전 필수 체크리스트**
> 1. ③ AI 점검 탭 → 시스템 프롬프트에서 **학교명을 본교 이름으로 변경**
> 2. 독서명·봉사 기관명이 규칙 위반으로 잡혀도 정상 동작 — 하나씩 확인 필요
> 3. API 오류가 잦으면 배치 크기 1 또는 유료 API 전환

**Q. 통합검사는 인터넷 연결이 필요한가요?**
글자수·규칙·중복 검사는 완전 오프라인입니다. 띄어쓰기 검사는 Ollama를 로컬에서 실행하므로 역시 인터넷이 불필요합니다. 규칙 업데이트 시에만 인터넷이 필요합니다.

**Q. Ollama 모델이 보이지 않습니다.**
`ollama serve` 명령으로 Ollama 서버를 먼저 실행하고, `ollama pull 모델명`으로 모델을 설치한 뒤 통합검사 탭을 다시 열면 목록이 갱신됩니다.

**Q. 글자수 기준이 실제 규정과 다릅니다.**
`rules/limits_YYYY.json` 파일을 직접 수정하거나, 4-5번 규칙 업데이트 기능으로 최신 파일을 내려받으세요.

**Q. 독서명이나 봉사활동 기관명이 위반으로 잡힙니다.**
규칙 검사에서 오탐이 발생할 수 있습니다. `rules/violations_YYYY.json`의 해당 패턴을 수정하거나, 결과를 참고만 하고 교사가 최종 판단하세요.

**Q. 처음 쓸 때 학교명을 어디서 바꾸나요?**
③ AI 점검 탭 → **시스템 프롬프트** 펼치기 → 학교명 수정 → **프롬프트 저장** 클릭. 되돌리려면 **기본값 복원** 사용.

**Q. API 호출 중 오류가 자주 납니다.**
무료 티어 분당 요청 한도(15 RPM) 초과가 원인입니다. 배치 크기를 1로 줄이거나 Google Cloud에서 결제 계정을 연결해 유료 티어로 업그레이드하세요.

**Q. 학년도가 바뀌면 어떻게 합니까?**
새 학년도 파일을 업로드하고 DB 구축을 다시 실행합니다. 이전 데이터는 `data/record.db.bak.{날짜}`로 자동 백업됩니다.

**Q. 학년 일부만 점검할 수 있나요?**
네. AI 점검 탭 또는 통합검사 탭에서 **학년·반·영역**을 선택해 범위를 한정하면 됩니다.
